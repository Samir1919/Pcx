catalog: data-driven component compatibility

Model PC-build component compatibility as admin-managed data (ADR 0018), so a
new socket / RAM type is added via CRUD — never a code or UI change:

- Migration 0060: reference_values (shared socket/memory_type vocabulary) and
  compatibility_rules (EQUALS between two category spec attributes) tables;
  spec_definitions gains SELECT data type + reference_key; CPU/Motherboard
  socket and CPU/Motherboard/RAM memory_type become SELECT; seeds sockets,
  memory types, and three rules.
- Domain: SELECT data type; createReferenceValue / createCompatibilityRule /
  evaluateCompatibility (generic EQUALS evaluation over rules + components).
- Backend: compatibility repository/service/HTTP (public read of reference
  values + rules, admin CRUD); the build-create command evaluates every active
  rule server-side and rejects incompatible builds (422
  CATALOG_COMPATIBILITY_CONFLICT).
- Admin: a Compatibility tab (reference values + rules CRUD) and SELECT spec
  dropdowns + a live compatibility banner in the PC builds configurator (all
  generic, data-driven).
