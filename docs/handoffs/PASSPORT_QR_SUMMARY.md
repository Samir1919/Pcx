# Agent Handoff: E7/E8 passport verification summary + listing QR

- Status: Complete
- Branch: main
- Latest commit: af30ddc
- Date: 2026-09-01

## Outcome

The public passport (`GET /passport/:pcxId`) now surfaces a server-derived
verification summary (grade + health narrative) and a scan-to-open QR encoding
the stable passport URL. Neither leaks private data; both are derived server-side
from approved disclosure fields.

## Changed areas

- `apps/api/src/modules/listing/listing-service.mjs` — `publicPassport` now
  computes and returns `verificationSummary` ("Independently inspected and
  verified by PCX: {grade} condition, {health}/100 health.").
- `apps/web/app/passport/[pcxId]/page.js` — renders the verification summary and
  a QR (via the `qrcode` library) encoding the stable `/passport/:pcxId` URL.
- `apps/web/app/globals.css` — `.qr` styles using `:root` tokens + fluid sizing.
- `apps/web/package.json` + `package-lock.json` — added `qrcode@^1.5.4`.
- `scripts/storefront-e2e-check.mjs` — added `passport-qr` assertion.
- `apps/api/test/listing-service.test.mjs` — verification summary assertions.

## Architecture/security review

- The QR URL is server-derived (`window.location.origin + /passport/:pcxId`); the
  SVG is generated by the `qrcode` library from that URL only (no user HTML).
- The verification summary uses only the public grade + health; no serial, cost,
  or private evidence is added.
